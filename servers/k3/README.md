# k3 — NixOS Media Server

Hostname: `k3` · IP: `192.168.20.26` · Role: Media server (Jellyfin + *arr stack)

## Hardware

| Component | Detail |
|-----------|--------|
| CPU | Intel, 6 cores, VT-x (`kvm-intel`) |
| RAM | 16 GB |
| OS Disk | `/dev/nvme0n1` — 238.5G NVMe (EFI + 8G swap + ext4 root) |
| Data Disk | `/dev/sda` — 1.8T HDD, mounted at `/mnt/data` |
| NIC | `eno1` — static `192.168.20.26/24`, gateway `192.168.20.1` |

## Media Stack (all native NixOS services)

| Service | Port | User | Data Dir | Purpose |
|---------|------|------|----------|---------|
| Jellyfin | 8096 | `jellyfin` | `/var/lib/jellyfin` | Media streaming |
| Sonarr | 8989 | `sonarr` | `/var/lib/sonarr/.config/NzbDrone` | TV series management |
| Radarr | 7878 | `radarr` | `/var/lib/radarr/.config/Radarr` | Movie management |
| Prowlarr | 9696 | `prowlarr` | `/var/lib/prowlarr` | Indexer aggregator |
| Jellyseerr | 5055 | `jellyseerr` | `/var/lib/jellyseerr/config` | Request management |
| qBittorrent | 8080 | `qbittorrent` | `/var/lib/qBittorrent` | BitTorrent client (torrent port 51413) |

All services run as systemd services under the `media` group (GID 2000).

## Storage Layout

```
/mnt/media/     ← NFS mount from NAS (192.168.20.31:/mnt/tank/media)
                   ├── TV/           (Sonarr managed)
                   ├── Movies/       (Radarr managed)
                   ├── downloads/    (qBittorrent downloads)
                   └── Downloads/    (alternate downloads)

/mnt/data/      ← Local 1.8T HDD (/dev/sda1, ext4)
                   Available for large local storage
```

```bash

# 2. On k3, pull and rebuild
ssh k3

git pull

```

## History: What We Did

### Phase 1 — Install NixOS via nixos-anywhere

- Installed NixOS 25.11 on k3 (was Fedora Atomic / Aurora), replacing the OS on `/dev/nvme0n1`
- Used `nixos-anywhere` from k4 (192.168.20.64), which already had Nix
- Config: static IP `192.168.20.26/24` on `eno1`, systemd-boot, 512M EFI + 8G swap + ext4 root
- Gotchas avoided: set `initialPassword = "changeme"`, SSH key + daemon enabled, static IP in config

### Phase 2 — Configure media services

- Added all six media services as **native NixOS modules** (no containers)
- Key design choice: native over podman for atomic updates, systemd integration, declarative config
- All services placed in shared `media` group (GID 2000) for NFS access
- NFS mount from NAS (`192.168.20.31:/mnt/tank/media` → `/mnt/media`)
- Local 1.8T HDD mounted at `/mnt/data` (available but unused currently)
- Sonarr/Radarr have native `group` option; Prowlarr/Jellyseerr use `DynamicUser` which we override to static users in `media` group
- Fixed `services.prowlarr.group` build error (option doesn't exist — used systemd override instead)

### Phase 3 — Migrate config from k1

- Ran `migrate-k1-to-k3.sh` which rsync'd configs from k1 (192.168.20.61, Fedora/Podman)
- Path remapping: container `/media/` → `/mnt/media/` everywhere
- Hostname remapping: container DNS names (`jellyfin`, `radarr`, `sonarr`) → `127.0.0.1`
- `UpdateMechanism` changed from `Docker` → `External` (services overwrote to `BuiltIn` on start — harmless, NixOS manages updates)
- qBittorrent: migrated config + active torrent state (`.torrent` + `.fastresume` files)
- Jellyseerr: migrated `settings.json` with API keys and service connections
- Jellyfin: migrated full data dir including database, metadata, plugins
- All *arr services: migrated SQLite databases with indexer/download client connections intact

### Current State

- All 6 services running and accessible on `192.168.20.26`
- Services are connected to each other (API keys preserved from k1)
- k1 (192.168.20.61) is **still running** its containers — both servers have active configs pointing at the same NFS media share
- Caddy on hub still routes `*.crussell.io` media subdomains to k1 (192.168.20.61)
