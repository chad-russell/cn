# Gloo Dev Stack → Nix Flake Migration Plan

## Current State (What We Have)

The Gloo dev stack runs on **hub** (Fedora Atomic, **not** NixOS). It's a complex patchwork:

### Components
| Layer | Tool | Where Defined |
|-------|------|---------------|
| Infra (postgres, rustfs, pgadmin) | Podman Compose | `servers/hub/dev-stacks/gloo/compose.yaml` |
| Env rendering (static + age secrets) | Bash script | `servers/hub/dev-stacks/gloo/scripts/render-runtime-env.sh` |
| DB/S3 init | Bash scripts | `servers/hub/dev-stacks/gloo/scripts/{init-db,init-buckets}.sh` |
| Per-service bootstrap (schema push, seed) | Bash scripts | `servers/hub/dev-stacks/gloo/scripts/bootstrap-{gpl,hb-api,storyhub,polymer}.sh` |
| App dev servers (6 services) | systemd user units | `brunch/config/hosts/hub/dev-stacks.bri` (Brioche-generated) |
| Reverse proxy | Caddy (system container) | `servers/hub/caddy/routes/internal/gloo.caddy` |

### Pain Points
1. **Brunch dependency** — systemd units are generated by a custom toolchain (brunch + brioche), adding cognitive overhead
2. **Scattered config** — env files, secrets, scripts, compose, systemd units, and brunch config are in 4+ directories
3. **Linuxbrew Node** — relies on `/home/linuxbrew/.linuxbrew/opt/node@24/bin` being present
4. **Impreparability** — no way to test or validate the stack config without deploying to hub
5. **Two sources of truth** — brunch owns the systemd units, but the Justfile/scripts also manage lifecycle

### Key Constraint
**Hub is Fedora Atomic, not NixOS.** We can't use `services.*` NixOS modules directly. Nix on hub is not installed. So "Nix treatment" means a **flake that produces runnable outputs** — not a NixOS configuration.

---

## Requirements (Restated)

1. **No source code changes** — existing Gloo repos stay untouched
2. **Toggle-able** — easy start/stop for individual services or groups
3. **Hot-reload friendly** — git pull in the repo → next.js/vite picks up changes
4. **Agent-friendly** — clear SKILL.md for AI agents
5. **Easy log access** — `journalctl` or equivalent

---

## Proposed Architecture

### Approach: Nix Flake → Systemd User Units + Podman Compose

The flake doesn't try to replace systemd or podman. Instead, it:

1. **Declares all service config in one place** (Nix expressions)
2. **Generates systemd unit files** at build time (not via brunch/brioche)
3. **Wraps compose + init scripts** into Nix-managed derivations
4. **Provides a dev shell** with all tools (node, pnpm, bun, age, awscli, just)
5. **Exposes CLI commands** via the flake's `apps` output

```
servers/hub/dev-stacks/gloo/
├── flake.nix              # ← Everything starts here
├── flake.lock
├── services/              # Nix module per app service
│   ├── gpl.nix
│   ├── hb-api.nix
│   ├── hb-web.nix
│   ├── storyhub.nix
│   ├── storyhub-worker.nix
│   └── polymer.nix
├── infra/                 # Infra definitions
│   ├── compose.nix        # Generates compose.yaml (or keeps it static)
│   ├── init-db.nix        # DB init script
│   └── init-buckets.nix   # S3 bucket init script
├── env/                   # Env template logic
│   └── render-env.nix     # Generates render-runtime-env from Nix attrsets
├── host-envs/             # (unchanged — static env files)
├── secrets/               # (unchanged — age-encrypted)
├── scripts/               # (unchanged — bootstrap scripts)
└── SKILL.md               # Agent instructions (rewritten)
```

### What the Flake Provides

#### 1. `nix run .#install` — Generate & install systemd units

Reads the Nix service definitions and writes unit files to `~/.config/systemd/user/`. Replaces the brunch/brioche generation entirely.

```nix
# services/gpl.nix example
{ service, path, port, execCmd, envFile, ... }:
{
  Unit = {
    Description = "Gloo ${service} dev server";
    After = [ "network-online.target" "gloo-infra.target" ];
    Wants = [ "network-online.target" ];
    PartOf = [ "gloo-all.target" ];
  };
  Service = {
    Type = "simple";
    WorkingDirectory = path;
    EnvironmentFile = envFile;
    ExecStart = execCmd;
    Restart = "on-failure";
    RestartSec = 2;
  };
  Install = { WantedBy = [ "gloo-all.target" ]; };
}
```

#### 2. `nix run .#up` / `nix run .#stop` — Lifecycle commands

Thin wrappers that call `systemctl --user` with the right targets.

#### 3. `nix run .#bootstrap` — First-time setup

Runs compose up → init-db → init-buckets → render envs → run bootstrap scripts.

#### 4. `nix develop` — Dev shell

```
$ nix develop
# Gets: node, pnpm, bun, age, awscli, just, podman, jq
```

No more linuxbrew dependency.

#### 5. Generated systemd targets (same structure as today)

| Target | Services |
|--------|----------|
| `gloo-infra.target` | compose-up (oneshot) + init-db + init-buckets |
| `gloo-all.target` | All 6 app services |
| `gloo-hummingbird.target` | hb-api + hb-web |
| `gloo-storyhub.target` | storyhub + storyhub-worker |

## Migration Steps (Implementation Order)

### Phase 0 — Prerequisites (hub)
- [ ] Install Nix on hub (single-user, via Determinate installer)
- [ ] Verify `nix develop` works
- [ ] Keep existing brunch-managed units running (don't break anything yet)

### Phase 1 — Flake skeleton
- [ ] Create `flake.nix` with inputs (nixpkgs, flake-utils)
- [ ] Define `devShells.x86_64-linux.default` with node, pnpm, bun, age, awscli, just
- [ ] Verify `nix develop` drops into a working shell on hub

### Phase 2 — Service definitions
- [ ] Create `services/*.nix` with each service's systemd unit config as a Nix attrset
- [ ] Create a `lib/build-units.nix` that merges all services into unit files
- [ ] Create `apps.x86_64-linux.install` that writes units to `~/.config/systemd/user/`

### Phase 3 — Infra & env
- [ ] Port `render-runtime-env.sh` logic into Nix (or keep the script, called from Nix)
- [ ] Port compose.yaml management (can stay static file, just referenced by Nix)
- [ ] Port init-db and init-buckets into `apps` outputs or keep as scripts

### Phase 4 — CLI apps
- [ ] `nix run .#gloo-up` — start infra + all services
- [ ] `nix run .#gloo-stop` — stop all services
- [ ] `nix run .#gloo-bootstrap` — full first-time bootstrap
- [ ] `nix run .#gloo-install` — generate and install systemd units
- [ ] `nix run .#gloo-status` — show status of all units

### Phase 5 — Cutover
- [ ] Stop brunch-managed units
- [ ] Remove brunch gloo unit definitions from `dev-stacks.bri`
- [ ] Run `nix run .#gloo-install && nix run .#gloo-up`
- [ ] Verify all services work
- [ ] Update Caddy if any port changes

### Phase 6 — SKILL.md & cleanup
- [ ] Rewrite `SKILL.md` to reference flake commands
- [ ] Remove `brunch/config/hosts/hub/gloo/` directory
- [ ] Remove `brunch/config/hosts/hub/dev-stacks.bri` gloo section (or whole file if buildspace is also migrated)
- [ ] Update root `AGENTS.md` if needed

## Open Questions / Decisions Needed

### Q1: Keep compose.yaml static or generate from Nix?
**Recommendation:** Keep it static. It's stable and rarely changes. Generating it from Nix adds complexity for no real benefit. The flake just references it.

### Q2: What about the buildspace stack?
**Recommendation:** Out of scope for this migration. Buildspace can stay on brunch-managed units. We can always migrate it later with the same pattern.

### Q3: Env files — Nix-managed or keep as flat files?
**Recommendation:** Keep as flat `.env` files in `host-envs/`. They contain service-specific config that changes independently of Nix. The render-runtime-env script stays as-is (copies + appends decrypted secrets). The flake just needs to know the path.

### Q4: Where does the flake live?
**Recommendation:** `servers/hub/dev-stacks/gloo/flake.nix` — same directory, just add Nix to what's already there.

### Q5: How does hot-reload work?
**Unchanged.** The systemd units run `next dev`, `vite dev`, etc. which watch for file changes. The git repos at `~/Gloo/360-*` are where the dev works. `git pull` → file change → dev server hot-reloads. The Nix layer only manages the *service wrapper*, not the source code.

### Q6: What about the linuxbrew Node dependency?
**Eliminated.** The dev shell provides Node/pnpm via nixpkgs. The systemd units get their PATH from the Nix store instead of `/home/linuxbrew/...`.

## What This Gives Us

| Before | After |
|--------|-------|
| 4 tools to understand (brunch, brioche, brunch config, systemd) | 2 tools (nix, systemd) |
| Linuxbrew Node dependency | nixpkgs-provided Node |
| Unit generation via brunch apply | `nix run .#install` |
| No validation before deploy | `nix build` / `nix flake check` |
| Scattered across repo | All gloo config in one flake |
| brunch is the only way to regenerate units | Standard Nix, reproducible anywhere |
